1. Network architecture and initial weights

The network has 3 inputs (e₁, e₂, e₃), 2 hidden neurons (P₁, P₂) with ReLU activation, and 1 linear output (pred). The initial weights come from the hand-drawn diagram:

Initial weights
// Default values of all 10 trainable parameters, from the diagram
var W_DEFAULT = {
  w11: 0.1,   w21: 0.26,  w31: 0.33,  b1: -1,   // → into P₁
  w12: 0.3,   w22: 0.24,  w32: 0.65,  b2: -1,   // → into P₂
  w4:  0.99,  w5:  0.89                           // → into output
};

// The weights training actually uses: your values if you set any (see below)
var W = loadStartWeights();

You can change the starting weights on the worked example page. Its simulator links carry your values in the link's query string (for example nn_training_simulator.html?w11=0.2&w21=0.26&…), and loadStartWeights() reads them. That page also saves your values in the browser, so a simulator opened directly, without one of those links, starts from them too. If neither is present, the simulator uses the defaults. Reset returns to whichever starting weights were loaded. The scaled worked example sends its own, scaled values the same way (see section 7).

The ground truth these weights need to learn is a simple weighted average:

grade = 0.2 * e₁ + 0.35 * e₂ + 0.45 * e₃

The network is overparameterized for this task — 10 weights to learn a function that only needs 3. It will converge to some weight combination that produces the correct outputs, but the internal weights won't match 0.2/0.35/0.45 directly because the hidden layer creates infinitely many equivalent mappings.

2. Forward pass — forward()

This function takes one student's exam scores and the current weights, and computes the prediction. It runs the three equations from the network diagram in order:

z₁ = w₁₁·e₁ + w₂₁·e₂ + w₃₁·e₃ + b₁ z₂ = w₁₂·e₁ + w₂₂·e₂ + w₃₂·e₃ + b₂ P₁ = max(0, z₁) P₂ = max(0, z₂) pred = w₄·P₁ + w₅·P₂
forward()
function forward(s, w) {
  // Hidden layer: weighted sum of inputs + bias
  var z1 = w.w11 * s.e1 + w.w21 * s.e2 + w.w31 * s.e3 + w.b1;
  var z2 = w.w12 * s.e1 + w.w22 * s.e2 + w.w32 * s.e3 + w.b2;

  // ReLU activation
  var p1 = relu(z1);
  var p2 = relu(z2);

  // Linear output (no activation)
  var pred = w.w4 * p1 + w.w5 * p2;

  return { z1, z2, p1, p2, pred };
}
Math
z₁ = w₁₁·e₁ + w₂₁·e₂ + w₃₁·e₃ + b₁
P₁ = max(0, z₁)
pred = w₄·P₁ + w₅·P₂
=
Code
z1 = w.w11*s.e1 + w.w21*s.e2 ...
p1 = relu(z1)
pred = w.w4*p1 + w.w5*p2

The function returns all intermediate values (z₁, z₂, P₁, P₂) because backpropagation needs them — the gradients depend on whether ReLU was active (z > 0) and what P₁/P₂ were.

3. ReLU and its derivative

The simplest functions in the entire codebase:

ReLU
function relu(x)  { return Math.max(0, x); }   // pass positive, kill negative
function reluD(x) { return x > 0 ? 1 : 0; }    // gradient: 1 if active, 0 if dead
ReLU(z) = max(0, z) ReLU'(z) = 1 if z > 0, else 0

The derivative is the key to understanding how gradients flow backward. When z > 0, the gradient passes through unchanged (multiplied by 1). When z ≤ 0, the gradient is killed entirely (multiplied by 0) — this is the "dying ReLU" effect.

With the starting weights, every z is positive for all three students, so on the first forward pass every gate is open. It doesn't stay that way at the default learning rate of 0.0001: the first update makes all three weights into P₁ negative, so z₁ is negative for every student from then on and P₁ never learns again. Section 7 shows the numbers.

4. Batched backpropagation — batchStep()

This is where the learning happens. One call to this function runs one full epoch: forward pass all 3 students, compute gradients, average them, update weights. It follows the chain rule backward through the network.

Step 1 — Compute loss and output gradient

L = ½(y − pred)² ∂L/∂pred = −(y − pred) = (pred − y)
Loss and output error
var err = f.pred - s.y;           // (pred − y) = ∂L/∂pred
totalLoss += 0.5 * err * err;     // ½(pred − y)² = L

Step 2 — Gradients for output weights (w₄, w₅)

∂L/∂w₄ = ∂L/∂pred · P₁ = (pred − y) · P₁ ∂L/∂w₅ = ∂L/∂pred · P₂ = (pred − y) · P₂
Output weight gradients
grads.w4 += err * f.p1;    // ∂L/∂w₄ = (pred−y) · P₁
grads.w5 += err * f.p2;    // ∂L/∂w₅ = (pred−y) · P₂

Step 3 — Chain rule through ReLU to hidden layer

The gradient flows backward from the output through w₄/w₅, then through the ReLU gate:

∂L/∂z₁ = ∂L/∂pred · w₄ · ReLU'(z₁) = (pred − y) · w₄ · ReLU'(z₁) ∂L/∂z₂ = ∂L/∂pred · w₅ · ReLU'(z₂) = (pred − y) · w₅ · ReLU'(z₂)
Through ReLU
var dLdz1 = err * W.w4 * reluD(f.z1);  // chain: output → w₄ → ReLU gate
var dLdz2 = err * W.w5 * reluD(f.z2);  // chain: output → w₅ → ReLU gate
If reluD(z) returns 0, the entire gradient for that neuron's weights becomes zero — nothing gets updated. This is why "dead neurons" are a problem in deep ReLU networks.

Step 4 — Gradients for hidden weights

Once we have ∂L/∂z₁ and ∂L/∂z₂, the gradient for each hidden weight is simply that value multiplied by the corresponding input:

∂L/∂w₁₁ = ∂L/∂z₁ · e₁ ∂L/∂w₁₂ = ∂L/∂z₂ · e₁ ∂L/∂w₂₁ = ∂L/∂z₁ · e₂ ∂L/∂w₂₂ = ∂L/∂z₂ · e₂ ∂L/∂w₃₁ = ∂L/∂z₁ · e₃ ∂L/∂w₃₂ = ∂L/∂z₂ · e₃ ∂L/∂b₁ = ∂L/∂z₁ ∂L/∂b₂ = ∂L/∂z₂
Hidden weight gradients
// Gradients into P₁
grads.w11 += dLdz1 * s.e1;   // ∂L/∂w₁₁ = ∂L/∂z₁ · e₁
grads.w21 += dLdz1 * s.e2;   // ∂L/∂w₂₁ = ∂L/∂z₁ · e₂
grads.w31 += dLdz1 * s.e3;   // ∂L/∂w₃₁ = ∂L/∂z₁ · e₃
grads.b1  += dLdz1;          // ∂L/∂b₁  = ∂L/∂z₁ · 1

// Gradients into P₂ (same pattern)
grads.w12 += dLdz2 * s.e1;   // ∂L/∂w₁₂ = ∂L/∂z₂ · e₁
grads.w22 += dLdz2 * s.e2;
grads.w32 += dLdz2 * s.e3;
grads.b2  += dLdz2;

Note the += — gradients are accumulated across all 3 students in the batch, then averaged in step 5.

Step 5 — Average and update

gradient_avg = (1/3) · Σ gradients w_new = w_old − η · gradient_avg
Batch average + weight update
// Average gradients over batch (3 students)
for (var k in grads) grads[k] /= n;

// Gradient descent: w = w - lr * gradient
for (var k in grads) W[k] -= lr * grads[k];

The lr (learning rate) controls the step size. Too small and convergence takes millions of epochs. Too large and the weights overshoot: the loss can blow up to NaN, but in this network a too-large step more often switches a ReLU neuron off for good, or makes the loss bounce back and forth forever. Both happen at the default of 0.0001 (see section 7). The simulator lets you change the learning rate in real time.

5. Training loop and convergence

The training loop calls batchStep() repeatedly. Each call is one epoch — one full pass over all 3 students. The loop stops when any of these conditions is met:

Stop conditions
if (loss < CONVERGED)  // Converged: 1e-10 here, 1e-6 and 1e-7 in the low and medium versions
if (epoch >= maxEpochs) // Hit the cap (user-configurable)
if (!isFinite(loss))   // Diverged — loss exploded to NaN/Infinity

On the scaled version, CONVERGED is divided by 100², so it means the same accuracy as on the original (see section 7). The auto-pause fires every 100,000 epochs so you can inspect the weights, adjust the learning rate, or stop early. Training runs asynchronously in batches of 500 steps with setTimeout(tick, 0) between batches so the browser stays responsive and the chart updates live.

The +100k and +1M buttons also run asynchronously in batches of 2,000 per tick, updating the UI between batches. This prevents the browser from freezing on long runs.

You can edit this table on the worked example page. Like the weights, your data travels in the simulator links and is saved in your browser, and loadTrainingData() reads it: s1, s2 and s3 hold each student's three exam scores and grade, and tw holds the real weights.

With only 3 data points and 10 parameters, the system is heavily underdetermined — there are infinitely many weight combinations that produce zero loss. The network will find one, but it won't be the "true" weights. This is a core concept in deep learning: the loss surface has many global minima, and gradient descent lands on whichever one is closest to the starting point.

7. Why training gets stuck, and the scaled version

At the default learning rate of 0.0001, the first update is far too big. Every prediction starts 46–69 points too high and the exam scores are 48–98, so the hidden-weight gradients run into the thousands (∂L/∂w₁₁ = 4,264.65). Multiplied by 0.0001, that moves w₁₁ by 0.43, from 0.1 to −0.33, and the other weights move by similar amounts. A step bigger than the weights themselves flips them negative instead of nudging them.

After step 1 (students 1, 2, 3): z₁ = −44.6, −45.1, −61.2 z₂ = −6.6, +4.35, −0.8

z₁ is negative for every student, so P₁ outputs 0 and reluD(z1) returns 0 for every student. No gradient reaches w₁₁, w₂₁, w₃₁ or b₁ again, and w₄'s gradient (err × P₁) is 0 too: P₁ is dead. P₂ survives only because student 2's z₂ is +4.35. It switches back on for everyone within a couple of epochs, but the steps are still too big, so from then on the loss alternates between 164.38 and 289.87 every epoch and never settles.

That margin is very thin. Change w₁₁ from 0.1 to 0.2 and every starting prediction is further off, so the first step is bigger, and student 2's z₂ ends up at −6.3. Now both neurons are dead, the network predicts 0 for every student, and the loss stays at 3,149.19, the average of ½·grade². That's higher than the starting loss of 2,091.5, so it looks like divergence, but nothing is changing at all.

Why a smaller learning rate alone isn't enough

A smaller learning rate keeps the neurons alive (3.2e-5 worked for every starting point we tried), but training gets very slow: at 5e-5, the loss takes about 1.7 million epochs to get below 1e-6. The underlying problem is the units. A weight multiplies an exam score near 100, but a bias multiplies 1, so changing a weight by 0.01 moves z by about 1 while changing a bias by 0.01 moves it by 0.01. A learning rate small enough to keep the weight steps safe leaves the biases crawling.

The scaled version

The scaled worked example divides the exam scores, the grades and the two biases by 100, and leaves the other weights and the real weights unchanged. That's the same network, just in different units:

e′ = e / 100 y′ = y / 100 b′ = b / 100 z′ = z / 100 P′ = P / 100 pred′ = pred / 100 L′ = L / 10,000

Now the weights and the biases both multiply numbers near 1, so they learn at similar speeds, and a standard learning rate of 0.1 works. The first step moves each weight by 0.03 to 0.05, no neuron switches off, and training converges in 5,181 epochs in the main simulator (3,200 and 3,695 in the low and medium versions). Scaling doesn't make every learning rate safe, though: at 1, the first step switches both neurons off, just as 0.0001 does in the original.

The scaled page's simulator links add lr=0.1 and scale=100 to the scaled values. The simulator starts its learning-rate slider at lr, and because every loss is 100² times smaller, it shrinks its convergence threshold by the same factor. The colours for a good or bad loss and error, and the number of decimals shown, are scaled the same way.

Settings from the link
var linkParams = new URLSearchParams(location.search);
var SCALE = Number(linkParams.get('scale')) > 0 ? Number(linkParams.get('scale')) : 1;
var CONVERGED = 1e-10 / (SCALE * SCALE);   // same accuracy as the unscaled version
